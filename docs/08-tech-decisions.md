# Технические решения и план разработки

## Выбранный подход

Для MVP используется одна веб-платформа с ролевой моделью и входом по ID участника. Дизайн сначала прорабатывается в Figma на основе списка экранов из `docs/07-screens.md`; затем интерфейс реализуется в коде.

## Стек MVP

| Область | Решение | Обоснование |
|---|---|---|
| Фронтенд | Next.js + TypeScript | Единый стек для интерфейса и серверных API, удобен для личного кабинета, ролей и SSR |
| Бэкенд | API-роуты Next.js на старте | Позволяет быстро запустить MVP без отдельного backend-сервиса |
| База данных | PostgreSQL | Подходит для связанных данных: пользователи, группы, ДЗ, отчёты, материалы |
| ORM | Prisma | Типобезопасная работа с PostgreSQL и понятные миграции |
| Аутентификация | E-mail + пароль, код подтверждения, вход по participant ID | Соответствует ТЗ и позволяет разделить доступы по ролям |
| Файлы | S3-совместимое хранилище | Подходит для документов, видео, изображений и материалов |
| Дизайн | Figma | Сначала макеты ключевых экранов, затем реализация в Next.js |
| Хостинг | Vercel + managed PostgreSQL + S3-хранилище | Быстрый старт, простое развертывание и масштабирование |

## Ролевая модель

- `guest` — просмотр открытого контента, регистрация, анкета, заявка.
- `student` — обучение, чат группы, форумы, ДЗ, отчёты, библиотека.
- `mentor` — группа, чат, форум, материалы, ДЗ, проверка работ.
- `admin` — пользователи, группы, модерация, расписание, аналитика.

## Правила доступа

- Глобальная роль пользователя и роль в конкретной группе могут различаться.
- `participant ID` выдаётся после успешного собеседования и является постоянным.
- Доступ к разделам определяется связкой пользователя, группы и роли в этой группе.
- Проверять и оценивать ДЗ может только наставник, который его создал.

## План разработки

### Этап 1. Каркас

- Инициализация Next.js + TypeScript + Prisma.
- Подключение PostgreSQL.
- Базовая структура приложения и дизайн-система.
- Регистрация, вход, подтверждение e-mail, восстановление пароля.

### Этап 2. Роли и группы

- Модель пользователя, групп и участия.
- Выдача participant ID.
- Создание групп модератором.
- Назначение учеников и наставников.
- Личный кабинет и выбор группы.

### Этап 3. Обучение

- Чат группы.
- Форумы наставников.
- Загрузка и сохранение материалов.
- Домашние задания, сдача и проверка.
- Регулярные отчёты.
- Расписание.

### Этап 4. Модерация

- Списки пользователей, кандидатов и заявок.
- Карточка участника.
- Модерация чатов и форумов.
- Публикация статей и объявлений.
- Базовая аналитика.

## Что не делаем в первой версии

- Конструктор платных курсов.
- Маркетплейс курсов и корзина.
- Оплата отдельных блоков.
- Электронная подпись и Госуслуги.
- Умный календарь для самостоятельной записи на собеседование.
- Бонусная программа.

## Первый результат разработки

Цель первого этапа — работающий каркас, в котором гость может зарегистрироваться, подтвердить e-mail, а участник — войти по ID и увидеть персональный личный кабинет.
